# MiaCode v2 安卓迁移计划

编制日期：2026-09-30，更新日期：2026-10-01。文档版本：0.2。目标为完整实现至 P5；进度与验收见 [P5 迁移记录](ANDROID_P5_WORKLOG_ZH.md)。独立 Android 工程位于 `D:\STUDY\Project_Work\MiaCode_dev2\MiaCode_Mobile`。

本计划以 MiaCode v2 的功能和文件兼容性为依据，制作面向安卓手机和平板的完整谱面创作应用。源码调查对应 `feature/qml-ui` 分支的 `c190bb2c`（版本标识为 `2.0.0-alpha`）。下文的技术路线、性能目标和工作量均为规划；安卓设备兼容性与导出性能需要通过原型和实机验证。

**产品定位是可在安卓设备上独立完成编辑、校验、预览和作品导出的本地创作工具。** 首版范围如下。

| 项目 | 首版要求 |
| --- | --- |
| 产品平台 | Android 手机、平板，强制横屏，按设备可用空间及比例适配 |
| 系统版本 | 暂定 Android 12 / API 31 起；构建 SDK、target SDK 与工具链在原型阶段确定 |
| 处理器架构 | ARM64 / `arm64-v8a`；首版暂不支持 32 位安卓系统 |
| 运行方式 | 编辑、分析、预览、MP4、WAV、封面及批量导出全部本机离线完成 |
| 功能范围 | 本计划列出的八组功能完整交付，并核对其在 v2 中的相关选项、参数和操作 |
| 后台导出 | 用户通过应用内设置决定是否启用，任务执行遵循系统生命周期与后台规则 |
| 发布形式 | 签名 Release APK，支持覆盖安装升级及数据迁移 |
| 工程互通 | 保留 simai / maidata 内容语义和已有工程素材约定，支持与 v2 交换作品 |
| 参考资料 | Visual Maimai Mobile 用于研究移动交互；v2 Linux 实现用于研究非 Windows 依赖适配 |

Android 版本、ABI、内存和 GPU 能力分别决定兼容性。ARM64 芯片上运行的 32 位系统也不属于首版支持范围。最低系统版本暂定为 Android 12，不等同于对所有该版本设备作出性能保证。

**功能完整性以用户可以完成的操作和得到的结果为准。** 原型阶段建立功能对照清单，记录每项功能的 v2 入口、参数、素材、结果和安卓验收证据；以下条目均处于计划状态。

当前 v2 的视频预设包含 30、60、120 FPS，以及 1:1、4:3、16:9 共十档尺寸，最高为 2560×1440。全部现有档位进入功能对照清单；安卓默认档位和推荐设备范围根据测试确定。硬件编码不支持某个组合时，需要验证本机软件路径；若某项能力尚未实现，按交付缺口记录并修复。

“结果一致”要求谱面语义、时间和可见内容一致。编码器、字体光栅化和 GPU 的数值差异按专门容差验收；MP4 文件字节一致不作为通过条件。平台相关的编码器选项映射为安卓有效的质量、速度和体积选项，并说明映射后的含义。

**架构采用 C++ 领域逻辑、Qt Quick/QML 移动界面和安卓系统接口。** 安卓拥有专用产品入口、页面装配、生命周期及发布配置；从 v2 迁入的模块保留清晰的所有权和数据契约。

`ChartWorkspace` 继续作为完整文档、当前难度、revision 和保存状态的权威。播放继续由统一控制器和音频时钟管理；时间轴、编辑器和预览通过快照交互。异步分析与任务回调携带文档或任务身份，页面重建和切换工程后拒绝过期结果。当前代码仍有 Session 装配和过渡存储耦合，实施时按功能拆出必要边界，实际复用比例由依赖闭包核查确定。

**界面以实际 v2 的 QML 工作区为依据。** 复用原版主题、标题栏、菜单、工具栏、编辑器、侧栏、预览及时间轴。手机和平板强制横屏，按屏幕比例调整面板空间，支持触摸与软键盘。主要界面与 v2 的相似度要求至少 90%，通过相同内容与主题的截图对照验收。

文本输入需要优先验证中文输入法的预编辑状态、长按选择、选择手柄、复制粘贴、撤销和滚动冲突。符号栏负责插入常用 simai 字符、移动光标及访问高频操作，并接入同一撤销历史。已有触控写谱能力通过相同文档命令入口使用。

Visual Maimai Mobile 的公开资料可用于研究可视化放置、Slide/Touch 绘制、选区操作和即时预览。第一阶段安排实机任务对照，记录完成一次选区编辑、定位和预览所需的步骤，再确定适合 MiaCode 的交互。本次已核对作者发布页与移动版文档，尚未完成 VMM APK 实机体验或其导出实现验证。

**工程文件采用授权来源与内部工作副本协作的方式。** 文件服务明确区分源工程、应用内部数据、临时缓存和最终输出。

1. 通过 Android Storage Access Framework 选择工程目录或文件，保存适用的持久 URI 授权；支持导入工程包及系统分享传入的素材。
2. 为音频、PV、字体和图片等需要普通路径的消费者准备内部工作副本，维护来源 URI、相对资源路径、内容版本与缓存之间的映射。
3. 内部自动恢复记录与用户保存分开。只有源工程回写成功，才更新对应保存点；授权失效、提供方不可写或空间不足时保留修改并给出处理入口。
4. 外部文件提供方的重命名、替换和原子写入能力逐项检测；采用临时写入、校验及可用的备份策略，确保失败后可恢复有效版本。
5. MP4、WAV、封面和工程包完成校验后写入用户选定位置；提供保存到媒体库或调用系统分享面板的入口。

字体导入到应用管理的字体库，同时保留项目引用信息。工程交换处理自定义字体和素材的缺失提示与路径重定位。应用内部工作副本需要明确的备份、导出和清理入口，避免用户将临时缓存视为唯一作品副本。新增应用侧预设或恢复数据使用版本化格式；已有谱面内容与元数据遵循 v2 的读写规则。

**音频和实时预览优先保留 v2 的时间与场景语义。** 安卓版 BASS、BASSmix 和所需扩展作为首轮音频候选，验证解码、波形、变速、打击音、离线混音和时钟行为。若某项依赖无法满足 ABI、运行或分发要求，在同一音频接口下评估替代后端，替代完成后重新进行语义与音质验收。

PV 解码优先验证仓库 QtAVPlayer 的 MediaCodec 路径，核对其与选定 Qt 版本、私有多媒体接口和图形后端的兼容性。需要覆盖旋转信息、色彩范围、seek、变速、首帧、结尾以及解码失败的软件回退。Qt 版本、NDK、JDK、Gradle/AGP 和原生依赖版本在原型通过后固定并记录。

Qt Quick 场景首先验证 OpenGL ES 路线，确认着色器、纹理格式、离屏目标及编码 Surface 的互操作。其他图形后端是否进入首版，由兼容性证据和维护成本决定。实时预览按设备能力调整刷新策略、缓存和资源准备，但最终导出始终遵循用户选择的尺寸、帧率和效果设置。

音频焦点丢失、耳机拔插、蓝牙切换、来电、屏幕旋转和恢复前台分别定义状态转换。播放暂停与恢复以音频设备状态和统一时钟为依据；后台导出使用自己的离线音频规划，避免与试听设备生命周期相互影响。

**导出使用固定输入快照和显式帧时间。** 一次任务提交时固定谱面、难度、分析结果、素材版本、字体、片头、范围和输出参数，使之后的编辑不会改变已提交任务。

| 封面输出 | 复用图层和谱面帧状态；编辑分辨率与最终输出分辨率分别管理 | 字体、文字换行、图层变换、图片方向、透明度、批量预设 |

FFmpeg 作为解码、滤镜、封装和软件编码能力的候选组件，在安卓进程内或经验证的独立编码边界集成。当前桌面导出使用独立的 GPL FFmpeg/libx264 程序，而预览使用 LGPL 共享库；迁移后的链接和分发边界需要结合 Qt、BASS 和所选编码器重新核对。硬件与软件编码的可分发方案均属于第一阶段的决策门槛；第三方组件进入 APK 前记录版本、来源、构建选项和许可材料。

硬件编码能力探测包含尺寸、帧率、profile、码率与实际初始化测试。软件后备需要在最高保留档位和代表性素材上验证可完成性；“编码器存在”不足以证明该组合可用。质量和体积预设分别对照结果与文件大小，给出有依据的安卓参数映射。

**后台导出由应用设置、安卓服务和持久化任务共同管理。** 后台开关默认关闭，用户可在开始导出时选择开启并保存偏好；普通前台导出始终可用。

| 情况 | 预期行为 |
| --- | --- |
| 前台导出 | 展示进度、预计剩余时间和取消入口；按用户设置保持屏幕或允许系统熄屏 |
| 开启后台导出后切换应用或锁屏 | 在适用的前台服务中继续执行，通过通知呈现进度和取消操作；按系统版本引导必要设置 |
| 关闭后台导出后离开前台 | 在安全边界暂停，保存任务状态；回到应用后提供继续操作 |
| 服务超时、资源不足或编码失败 | 保存可靠进度与错误原因，释放资源，提供恢复或重试 |
| 系统回收进程或设备重启 | 重新打开应用时恢复队列和已完成输出；当前任务按有效检查点恢复或重做未完成部分 |
| 用户强行停止应用 | 停止运行；用户再次启动后检查未完成任务并提供恢复入口 |

服务宿主优先验证独立导出进程方案，以隔离重型任务与编辑界面。安卓服务、Qt 事件循环、QML 引擎、离屏 GPU 上下文及音频解码各自明确所属线程与生命周期；此组合能否在锁屏和界面重建后稳定工作必须在第一阶段实测。若独立服务进程路线未通过，评估其他安卓宿主实现，保持固定快照、任务恢复与资源所有权要求。

现代 Android 对部分媒体处理前台服务设有后台累计时限。长任务按可恢复的片段或检查点落盘；恢复时核对输入内容和参数，重做尚未完成的片段。分段后的帧时间连续性、关键帧、音频样本和最终拼接列为验收项目。通知设置、电池策略和后台开关分别处理，系统设置不会被视为无限运行保证。

初步总量为 24–37 人周，作为投入讨论范围。P0 完成后根据编码、后台渲染和输入法结果重新估算；该数字不等于固定交付日期。P0 的关键路径未验证时，后续可以推进独立工作，但完整发布的承诺必须保留对应阻塞项。后续阶段通过原型逐步扩充功能，最终发布以 F01–F08 全部满足为条件。

**验收使用固定样本、自动化规格和实机任务三类证据。** 样本集在 P0 冻结，包含多 BPM、`&first` 偏移、复杂 Slide/Touch、无头及特殊修饰、注释和扩展字段、多难度、异常语法、高密度谱、不同音频和 PV、自定义字体与多图层封面。

| 验收域 | 检查内容 | 判定原则 |
| --- | --- | --- |
| 文档与变换 | 读写、难度、元数据、注释、整理、撤销和保存状态 | 同一输入的有效语义保持；需要原样保留的字段和文本按 v2 契约验证 |
| 解析与无理 | 音符类型、时间、诊断类别、位置和参数边界 | 与固定 v2 结果对照；浮点容差明确定义，差异必须有解释和审阅 |
| 同步与渲染 | 播放、seek、变速、选区、时间轴、场景层级与特效 | 以共同时间源和固定时刻对照，禁止累计漂移；视觉差异使用固定帧检查 |
| 音视频输出 | 片头、起止区间、帧数、时间戳、混音、尾部和批量结果 | 帧数与计划相符，时间戳连续；同一音效事件落在预期采样位置，封装延迟单独处理 |
| 封面 | 字体、换行、图层顺序、变换、图片、谱面帧和批量预设 | 同一输入与布局参数得到可对照结果，文字不缺字、图层不丢失 |
| 生命周期 | 旋转、分屏、锁屏、来电、蓝牙、权限撤销、进程回收和升级 | 文档可恢复，旧回调不会污染新状态，任务恢复不混用输入 |
| 性能与资源 | 长谱输入、分析延迟、预览帧时间、导出速度、内存和温度 | 在代表设备上冻结量化指标；低性能时有可预期反馈，持续任务无失控增长 |

P0 同时形成性能指标表，记录设备型号、系统、输入规模、测试方法、目标值和实测值。编辑响应、分析完成时间、预览帧时间、同步误差和导出倍速分别评估；每项指标注明冷启动、热运行及是否带 PV。120 FPS 导出属于离线逐帧生成能力，实际计算速度和屏幕刷新率分别记录。

复用现有 `docs/tests/SPEC_CATALOG.md` 中适用的文档、解析、无理、时间轴、场景和导出规划规格。主机规格验证确定性逻辑；安卓上的文件授权、输入法、音频、GPU、MediaCodec、服务和恢复需要设备级验证。首版 APK 的完整通过结论必须包含实机证据。

**主要风险按最早发现、对应处理和发布门槛管理。**

| 风险 | 影响 | 处理与门槛 |
| --- | --- | --- |
| 服务中离屏 Qt Quick 渲染与界面生命周期耦合 | 锁屏或界面重建后导出停滞 | P0 验证服务宿主、事件循环和独立上下文；未通过前保留为完整后台导出的阻塞项 |
| 软件编码后备的能力与依赖分发边界 | 部分设备或输出档位不可完成 | P0 确定可分发路径并验证代表输入，P4 覆盖全部保留档位 |
| BASS/扩展或 QtAVPlayer 的安卓兼容性 | 音频、波形、PV 或时钟异常 | 固定依赖版本和所需能力，必要时替换接口内实现；替换后进行语义与设备验证 |
| 文档 URI 与第三方库路径接口不同 | 工程素材读取、回写或授权恢复失败 | 统一来源与工作副本映射；文件提供方能力检测及失败恢复纳入 P1 |
| 自定义选区与移动输入法冲突 | 长谱编辑效率或正确性下降 | P0 验证核心输入，P2 完成输入法、触摸及键盘组合测试 |
| 热降频、内存及临时存储压力 | 长任务性能下降、失败或被系统回收 | 控制缓存、并发及检查点大小，开展持续负载测试并定义设备推荐范围 |
| 新版系统规则与 16 KB 原生库要求 | 安装、运行或后台任务不兼容 | 验证全套原生依赖及签名 APK，发布前重新核对系统行为 |
| 功能迁移遗漏 | 具备入口但无法完成完整工作流 | 为 F01–F08 建立参数级清单与场景证据，所有缺口关闭后进入正式发布 |

当前待决项为：最低系统版本的最终确认、具体 Qt/NDK 工具链、代表设备和最低资源要求、默认导出档位、软件编码后备、服务渲染宿主、性能与视觉容差指标。各项均在 P0 给出候选、证据和决定；后续因实测需要调整产品能力边界时，先更新本计划和验收清单。

**交付材料随实现同步维护。** 最终提供安卓工程及依赖构建说明、可复现的 APK 打包与签名流程、签名 Release APK、功能对照清单、设备兼容记录、作品对照样本、已知限制、恢复说明和版本升级说明。签名密钥通过独立安全存储管理；文档和仓库中保留使用流程。

在独立 Android 工程执行开发时，构建统一使用 `build-devtools` 下的构建目录，默认 Release；遵循最多 4 个任务、同一工程一次构建的规则。每次提交或推送前审阅差异、格式和风险，并执行与变更相匹配的验证。当前处于实现阶段，最终交付要求完整 P5 验收。
